# PW Aquatics — REST API

> Status: **Proposal — awaiting owner approval.** Once implemented, the OpenAPI
> spec generated by springdoc (`/api/v3/api-docs`, Swagger UI in dev only) is
> the authoritative contract; this document describes the intended design.

---

## 1. Conventions

### 1.1 Basics

| Topic | Convention |
|---|---|
| Base path | `/api/v1` (same origin as the SPA) |
| Format | JSON, UTF-8. `Content-Type: application/json`; uploads use `multipart/form-data` |
| Naming | JSON fields `camelCase`; URL paths `kebab-case`; enum values `UPPER_SNAKE_CASE` |
| IDs | UUID strings. Public URLs use product `slug` and `orderNumber` |
| Timestamps | ISO 8601 UTC, e.g. `"2026-11-20T10:30:00Z"`; dates as `"2026-11-24"` |
| Money | `{ "amount": 1299, "currency": "EUR" }` — `amount` is an integer in **minor units** (cents), gross incl. VAT |
| Versioning | URL version (`/v1`). Breaking changes → `/v2`; additive changes are not breaking |
| Language | `Accept-Language: de` / `en` for localised messages and content |

### 1.2 Authentication and CSRF

- Session cookie (`SESSION`, `HttpOnly`, `Secure`, `SameSite=Lax`) created by
  `POST /auth/login`. No tokens in `localStorage`.
- CSRF: the server sets a readable `XSRF-TOKEN` cookie; every `POST`, `PUT`,
  `PATCH` and `DELETE` must send it back as the `X-XSRF-TOKEN` header.
  Exception: payment-provider webhooks (verified by signature instead).
- Guest carts: `CART_TOKEN` cookie (`HttpOnly`), handled transparently by the server.

**Access levels used below:** `public` · `customer` (logged in, any role) ·
`admin` (role `ADMIN`). Customer resources are always scoped to the current
user — another user's resource returns `404`, not `403`, to avoid leaking existence.

### 1.3 Pagination, sorting, filtering

```
GET /api/v1/products?page=0&size=24&sort=price,asc
```

```json
{
  "items": [ ... ],
  "page": 0,
  "size": 24,
  "totalItems": 137,
  "totalPages": 6
}
```

`size` max 100. Multi-value filters are repeated or comma-separated:
`?colour=blue&colour=red` ≡ `?colour=blue,red`.

### 1.4 Error format

All errors use **RFC 9457 Problem Details** (`application/problem+json`) with a
stable `code` the frontend can switch on:

```json
{
  "type": "about:blank",
  "title": "Insufficient stock",
  "status": 409,
  "detail": "Only 4 animals of 'Blue Dream' are available.",
  "code": "INSUFFICIENT_STOCK",
  "instance": "/api/v1/checkout/orders",
  "traceId": "4f1c2a…",
  "errors": [
    { "field": "items[0].quantity", "code": "INSUFFICIENT_STOCK", "message": "Max. 4 available" }
  ]
}
```

| HTTP | Typical `code` values |
|---|---|
| 400 | `VALIDATION_FAILED`, `MALFORMED_REQUEST` |
| 401 | `UNAUTHENTICATED`, `INVALID_CREDENTIALS` |
| 403 | `FORBIDDEN`, `CSRF_INVALID`, `EMAIL_NOT_VERIFIED` |
| 404 | `NOT_FOUND` |
| 409 | `SLUG_TAKEN`, `SKU_TAKEN`, `SCIENTIFIC_NAME_TAKEN`, `IN_USE`, `INSUFFICIENT_STOCK`, `PRODUCT_UNAVAILABLE`, `CART_EMPTY`, `CART_CHANGED`, `PRICE_CHANGED`, `SHIPPING_PAUSED`, `SHIPPING_METHOD_UNAVAILABLE`, `PAYMENT_METHOD_UNAVAILABLE`, `ORDER_NOT_CANCELLABLE`, `INVALID_STATUS_TRANSITION`, `CONFLICT` (optimistic lock), `DUPLICATE` |
| 422 | `CART_FULL`, `VERSION_REQUIRED`, `SLUG_INVALID`, `NO_ACTIVE_VARIANT`, `NO_IMAGE`, `SPECIES_RESTRICTED`, `LAST_IMAGE`, `IMAGE_TYPE_UNSUPPORTED`, `IMAGE_INVALID`, `IMAGE_TOO_LARGE`, `IMAGE_TOO_SMALL`, `IMAGE_LIMIT_REACHED`, `IMAGE_ORDER_INVALID`, `COMPARE_AT_PRICE_INVALID`, `VARIANT_INVALID`, `CATEGORY_CYCLE`, `RANGE_INVALID`, `ADJUSTMENT_INVALID`, `STOCK_NEGATIVE`, `STATS_RANGE_INVALID`, `TOKEN_INVALID`, `PASSWORD_TOO_WEAK`, `CURRENT_PASSWORD_INVALID`, `EMAIL_TAKEN`, `EMAIL_UNCHANGED`, `ADDRESS_LIMIT_REACHED`, `COUNTRY_INVALID`, `COUPON_INVALID`, `COUPON_EXPIRED`, `COUPON_MIN_ORDER_NOT_MET`, `COUPON_USAGE_LIMIT_REACHED`, `LIVE_ANIMAL_CONDITIONS_REQUIRED` |
| 413 | `FILE_TOO_LARGE` (uploads over 15 MB) |
| 423 | `ACCOUNT_LOCKED` |
| 429 | `RATE_LIMITED` (with `Retry-After` header) |
| 500 | `INTERNAL_ERROR` (no stack traces or internals in the body) |

### 1.5 Idempotency and concurrency

- `POST /checkout/orders` requires an `Idempotency-Key` header (16–100 characters of
  `A–Z a–z 0–9 _ -`, e.g. a UUID, generated by the client per checkout attempt).
  Repeating the request with the same key returns the order created the first time.
  The client keeps the key when the answer was lost (network error, 5xx) and takes a
  new one after the server refused the attempt (4xx).
- Admin updates of products, orders and coupons send the `version` they edited;
  a stale version returns `409 CONFLICT`.

### 1.6 Server-side authority

The API **ignores** any price, total, discount, tax or stock value sent by a
client. Requests contain only identifiers and quantities; every amount in a
response is calculated by the server.

## 2. Endpoint overview

### 2.1 Auth — `/api/v1/auth`

| Method | Path | Access | Description |
|---|---|---|---|
| GET | `/auth/csrf` | public | Ensures the `XSRF-TOKEN` cookie is set (called on app start) |
| POST | `/auth/register` | public | `{ email, password, firstName, lastName, marketingOptIn? }`. Sends a verification email. Always `202` |
| POST | `/auth/login` | public | `{ email, password }` → `200` session view + `SESSION` cookie (new session id on every login). The guest cart is merged on the next cart request (§2.4) |
| POST | `/auth/logout` | public | Ends the session; `204` even without one |
| GET | `/auth/me` | public | `{ "authenticated": true, "user": { id, email, firstName, lastName, role } }` or `{ "authenticated": false, "user": null }` |
| POST | `/auth/verify-email` | public | `{ token }` from a registration **or** email-change email → `204` |
| POST | `/auth/resend-verification` | public | `{ email }` → always `202` |
| POST | `/auth/forgot-password` | public | `{ email }` → always `202` |
| POST | `/auth/reset-password` | public | `{ token, newPassword }` → `204`; ends all sessions of the user |

**Rules**

- **Login requires a verified email address.** Passwords: 10–128 characters, no
  composition rules, obvious choices rejected (`422 PASSWORD_TOO_WEAK`).
- **No account enumeration.** Register, resend and forgot-password always answer
  `202`; only the email that is sent differs (an existing address gets a "you
  already have an account" email, and its password is never replaced). Unknown
  address and wrong password both give `401 INVALID_CREDENTIALS`.
- **What is revealed only after the correct password:** `403 EMAIL_NOT_VERIFIED`
  and `423 ACCOUNT_LOCKED` (locked by an administrator).
- **Brute force:** after 10 wrong passwords in a row the account is locked for
  15 minutes; attempts are also limited per address (whether or not an account
  exists) and per IP. All three answer `429 RATE_LIMITED` with `Retry-After`,
  so a temporary lock does not reveal that the account exists.
- Emailed links are single-use (`422 TOKEN_INVALID` otherwise): verification
  and email change 48 h, password reset 1 h. Only a SHA-256 hash is stored.
- Emails are sent in the language of the request (`Accept-Language`: `en`/`de`).

### 2.2 Catalog — public

| Method | Path | Description |
|---|---|---|
| GET | `/products` | List with filters (see below) |
| GET | `/products/facets` | Filter options with counts for the current filter set |
| GET | `/products/{slug}` | Product detail |
| GET | `/products/{slug}/related` | Same species / category suggestions |
| GET | `/categories` | Category tree |
| GET | `/species` | Species list |
| GET | `/species/{slug}` | Species profile incl. care parameters |
| GET | `/colours` | Colour list |
| GET | `/grades` | Grade list |

**`GET /products` and `GET /products/facets` query parameters**

| Param | Example | Notes |
|---|---|---|
| `q` | `blue` | Text search on product name and species names (max 100 chars) |
| `category` | `neocaridina` | Category slug, includes sub-categories |
| `species` | `neocaridina-davidi` | Multi-value (repeated or comma-separated) |
| `colour` | `blue,red` | Multi-value |
| `grade` | `sss` | Multi-value |
| `minPrice`, `maxPrice` | `500`, `3000` | Cents, compared with the cheapest active variant |
| `availability` | `IN_STOCK` | `IN_STOCK` (incl. low stock), `COMING_SOON`, `ALL` (default) |
| `featured` | `true` | Featured products only |
| `sort` | `PRICE_ASC` | `RELEVANCE` (default), `NEWEST`, `PRICE_ASC`, `PRICE_DESC`, `NAME_ASC`, `GRADE_DESC` |
| `page`, `size` | `0`, `24` | Zero-based page; size 1–100, default 24 |

Only `ACTIVE` products of species that are not trade-restricted are ever returned.
`RELEVANCE` lists purchasable products first, then "coming soon", then sold out;
within each group featured first, then newest. Invalid values → `400 VALIDATION_FAILED`.

**Product summary (list item)**

```json
{
  "id": "0193…",
  "slug": "blue-dream-high",
  "name": "Blue Dream",
  "species": { "slug": "neocaridina-davidi", "scientificName": "Neocaridina davidi", "commonName": "Neocaridina shrimp" },
  "category": { "slug": "neocaridina", "name": "Neocaridina" },
  "grade": { "slug": "high", "name": "High" },
  "colours": [ { "slug": "blue", "name": "Blue", "hexCode": "#1565C0" } ],
  "priceFrom": { "amount": 390, "currency": "EUR" },
  "compareAtPriceFrom": null,
  "hasMultipleVariants": true,
  "availability": "LOW_STOCK",
  "liveAnimal": true,
  "primaryImage": {
    "url": "/media/products/7f3a…/800.webp",
    "srcSet": "/media/products/7f3a…/400.webp 400w, /media/products/7f3a…/800.webp 800w",
    "alt": "Blue Dream shrimp on moss",
    "width": 1600, "height": 2000
  },
  "secondaryImage": null
}
```

`availability` is derived on the server: `IN_STOCK`, `LOW_STOCK`, `COMING_SOON`,
`OUT_OF_STOCK` (rules in DATABASE.md §3.2).

**Product detail** (`GET /products/{slug}`) adds `shortDescription`,
`descriptionHtml` and `careNotesHtml` (sanitised HTML rendered from Markdown),
`species` (with `care`: temperature, pH, GH, KH, TDS, size, lifespan, difficulty
— every value nullable), `categoryPath` (root first, for breadcrumbs),
`availableFrom`, `images[]`, `seo` and:

```json
"variants": [
  { "id": "0193…a1", "sku": "BLUE-DREAM-PREMIUM-1", "name": "1 animal", "packSize": 1,
    "price": { "amount": 590, "currency": "EUR" }, "compareAtPrice": null,
    "available": true, "maxQuantity": 6 },
  { "id": "0193…a2", "sku": "BLUE-DREAM-PREMIUM-10", "name": "10 animals", "packSize": 10,
    "price": { "amount": 5200, "currency": "EUR" }, "compareAtPrice": null,
    "available": false, "maxQuantity": 0 }
]
```

Exact stock numbers are never exposed: `maxQuantity` (packs that can be bought
now) is capped at 20, and low stock is only signalled as `availability: LOW_STOCK`.

**Facets** (`GET /products/facets`): options with counts for the current search.
Each dimension is counted *without its own filter*, so other options in the same
group stay selectable.

```json
{
  "species": [ { "slug": "neocaridina-davidi", "name": "Neocaridina shrimp", "hexCode": null, "count": 9 } ],
  "colours": [ { "slug": "blue", "name": "Blue", "hexCode": "#1565C0", "count": 2 } ],
  "grades":  [ { "slug": "high", "name": "High", "hexCode": null, "count": 3 } ],
  "availability": { "inStock": 14, "comingSoon": 1 },
  "price": { "min": { "amount": 190, "currency": "EUR" }, "max": { "amount": 1390, "currency": "EUR" } }
}
```

`GET /products/{slug}/related` returns up to 4 visible products: same species
first, then same category; purchasable ones first.

**Response conventions for generated types:** every property of a response
object is always present (marked `required` in OpenAPI); properties that can be
`null` are published as nullable. Request bodies are named `*Request`.

### 2.4 Cart — `/api/v1/cart` (public; guest or customer)

| Method | Path | Body | Description |
|---|---|---|---|
| GET | `/cart` | — | Current cart (an empty cart if there is none; never creates one) |
| POST | `/cart/items` | `{ variantId, quantity }` | Add packs (on top of an existing line). Creates the cart if needed |
| PATCH | `/cart/items/{itemId}` | `{ quantity }` | Set the quantity of a line |
| DELETE | `/cart/items/{itemId}` | — | Remove a line |
| DELETE | `/cart` | — | Empty the cart |

`PUT /cart/coupon` and `DELETE /cart/coupon` follow with coupons (Phase 8).

**Who owns the cart**

- **Guests:** an `HttpOnly`, `SameSite=Lax` cookie `CART_TOKEN` (random 256-bit
  token, 30 days, renewed on every change). Only its SHA-256 hash is stored.
- **Customers:** one cart per account, found through the session.
- **After signing in:** the next cart request carries both the session and the
  guest cookie; the guest cart is merged into the account's cart (quantities
  summed, capped at the available stock) and the cookie is deleted. The cart then
  belongs to the account and is there again after signing out and in.

**Rules**

- Requests contain only ids and quantities (`quantity` 1–20). Any price field a
  client sends is ignored; prices, totals and VAT come from the catalog.
- Adding or changing: unknown variant → `404`; product not purchasable →
  `409 PRODUCT_UNAVAILABLE`; more than is in stock → `409 INSUFFICIENT_STOCK`;
  more than 50 different products → `422 CART_FULL`.
- A line of another visitor's cart → `404`.
- The cart does not reserve stock (that happens when the order is placed).
  On every read it is recalculated: a quantity above the available stock is
  lowered and saved (`QUANTITY_REDUCED`, reported once); a product that cannot be
  bought right now stays in the cart as `available: false`, is excluded from the
  totals and reported as `ITEM_UNAVAILABLE` until it is removed or back in stock.

Every call returns the full, recalculated cart:

```json
{
  "items": [
    {
      "id": "0193…c1",
      "variantId": "0193…a1",
      "productSlug": "blue-dream-high",
      "productName": "Blue Dream",
      "variantName": "1 animal",
      "speciesName": "Neocaridina davidi",
      "gradeName": "High",
      "categorySlug": "neocaridina",
      "colourHex": "#1565C0",
      "image": null,
      "quantity": 3,
      "maxQuantity": 12,
      "unitPrice": { "amount": 390, "currency": "EUR" },
      "lineTotal": { "amount": 1170, "currency": "EUR" },
      "available": true
    }
  ],
  "totals": {
    "subtotal":    { "amount": 1170, "currency": "EUR" },
    "total":       { "amount": 1170, "currency": "EUR" },
    "includedTax": { "amount": 187,  "currency": "EUR" }
  },
  "itemCount": 3,
  "warnings": [
    { "code": "QUANTITY_REDUCED", "itemId": "0193…c1", "productName": "Blue Dream", "quantity": 3 }
  ]
}
```

`itemCount` is the number of packs in available lines (header badge). `total`
equals `subtotal` until shipping and coupons exist. Warning codes:
`QUANTITY_REDUCED`, `ITEM_UNAVAILABLE`, `ITEM_REMOVED`. A changed price needs no
warning here because the cart always shows the current price; the checkout
compares the total the customer saw with the server's (`PRICE_CHANGED`, Phase 5).

### 2.5 Checkout — `/api/v1/checkout` (customer)

Signed-in customers only. The customer and the cart always come from the session; a
request names an address of the customer and a shipping method, never items or prices.

| Method | Path | Description |
|---|---|---|
| GET | `/checkout/shipping-methods?country=DE` | Methods for the cart and a destination, with prices and dispatch dates |
| POST | `/checkout/quote` | Price breakdown for the cart, an address and a shipping method |
| POST | `/checkout/orders` | Place the order (requires `Idempotency-Key`, §1.5) → `201` |

Every call checks the cart first: empty → `409 CART_EMPTY`; a line that is no longer
available in the wanted quantity (also counting all pack sizes of a product together) →
`409 CART_CHANGED`. The checkout never changes quantities itself — the customer goes
back to the cart, which shows what changed (§2.4).

**`GET /checkout/shipping-methods`**

```json
{
  "methods": [
    {
      "code": "DHL_LIVE_DE",
      "name": "DHL Express – Germany",
      "description": "Insulated box, dispatched Monday to Wednesday.",
      "carrier": "DHL",
      "price": { "amount": 990, "currency": "EUR" },
      "freeFrom": null,
      "plannedDispatchDate": "2027-03-08",
      "estimatedDeliveryFrom": "2027-03-09",
      "estimatedDeliveryTo": "2027-03-09"
    }
  ],
  "paused": false,
  "pauseMessage": null,
  "pausedUntil": null
}
```

- Only methods that deliver to the country and may carry the cart (live animals need a
  method that allows them). No method → `methods` is empty.
- `price` is `0` once the goods value reaches the method's `freeFrom` threshold.
- `plannedDispatchDate` is the **earliest** dispatch day: the first dispatch weekday of
  the method that is at least `SHIPPING_HANDLING_DAYS` (default 1) after today, in the
  shop's time zone. Public holidays are not considered yet.
- **Shipping pause** (shop setting `shipping.pause`, live animals only): with an end date
  the dispatch date moves behind it (`paused: true`, `pausedUntil`); without an end date
  no methods are offered and quote/order answer `409 SHIPPING_PAUSED`.

**`POST /checkout/quote`**

```json
{ "shippingAddressId": "0193…", "shippingMethodCode": "DHL_LIVE_DE" }
```

Response: `items` (cart lines with current names, prices and `lineTotal`), `totals`
(`subtotal`, `shipping`, `total`, `includedTax`), the chosen `shippingMethod` (as above),
`containsLiveAnimals` and the `paymentMethods` that can be used right now
(`["BANK_TRANSFER"]`; empty while the shop's bank account is not configured).
Another customer's address → `404`; a method that does not fit → `409 SHIPPING_METHOD_UNAVAILABLE`.

**`POST /checkout/orders`**

```json
{
  "shippingAddressId": "0193…",
  "billingAddressId": null,
  "shippingMethodCode": "DHL_LIVE_DE",
  "paymentMethod": "BANK_TRANSFER",
  "customerNote": "Please ring twice.",
  "acceptedTerms": true,
  "acceptedLiveAnimalConditions": true,
  "expectedTotal": { "amount": 1770, "currency": "EUR" }
}
```

- `billingAddressId` omitted or `null`: billed to the shipping address. Addresses are
  always saved addresses of the customer (a new one is created through §2.6 first).
- `acceptedTerms` must be `true` (`400 VALIDATION_FAILED`); with live animals in the
  cart `acceptedLiveAnimalConditions` must be `true` too
  (`422 LIVE_ANIMAL_CONDITIONS_REQUIRED`).
- `expectedTotal` is **not** used for pricing. If it differs from the server's total the
  request fails with `409 PRICE_CHANGED`, so nobody pays an amount they have not seen.
- Unknown fields such as items or prices are ignored.
- Other refusals: `409 PAYMENT_METHOD_UNAVAILABLE`, `409 INSUFFICIENT_STOCK` (final
  guard while taking the stock), `429 RATE_LIMITED`.

In one transaction the server locks the cart and the products, checks everything
again, takes the animals out of stock, stores the order with snapshots of items, prices
and addresses, empties the cart and queues the confirmation email.

`201 Created`:

```json
{
  "orderNumber": "PW-2027-000123",
  "status": "PENDING_PAYMENT",
  "paymentStatus": "UNPAID",
  "total": { "amount": 1770, "currency": "EUR" },
  "paymentDueAt": "2027-03-08T22:59:59Z",
  "paymentInstructions": {
    "type": "BANK_TRANSFER",
    "accountHolder": "PW Aquatics",
    "iban": "DE…",
    "bic": "…",
    "bankName": "…",
    "reference": "PW-2027-000123",
    "amount": { "amount": 1770, "currency": "EUR" }
  }
}
```

An unpaid bank-transfer order expires at the end of the day `ORDER_BANK_TRANSFER_PAYMENT_DAYS`
(default 7) after it was placed: a job cancels it, returns the animals to stock and
emails the customer.

## 3. Admin API — `/api/v1/admin` (role `ADMIN`)

Every write is recorded in the audit log.

### 3.1 Dashboard and statistics

Built ahead of Phase 8 (coupon statistics follow with coupons). Read only; implemented as a
read model in the `admin` module.

**Periods.** `from` and `to` are ISO dates, both inclusive, on the shop's calendar
(Europe/Berlin). Without them the last 30 days up to today are used. A period may be at most
731 days; `to` before `from` or a longer period → `422 STATS_RANGE_INVALID`; a malformed date →
`400`. The bucket size follows the length: up to 31 days per day, up to 182 days per week
(Monday–Sunday), longer per month. Every figure is compared with the period of the same length
directly before (`period.previousFrom`/`previousTo`).

**Definitions.** A *sale* is an order that is neither cancelled (expired unpaid orders are
cancelled too) nor refunded, counted on the day it was placed. Amounts are gross (incl. VAT);
order totals include shipping, product and category figures use line totals (goods only).
*Paid* means `paymentStatus` `PAID` or `PARTIALLY_REFUNDED`. *Animals* are packs × animals per
pack of live-animal lines. Changes and shares are in basis points (`changeBps`: +12.5 % = 1250;
`null` when the previous value was 0). All figures, shares and averages are calculated by the
server (half-up rounding); the admin pages only format them.

| Method | Path | Description |
|---|---|---|
| GET | `/admin/dashboard` | Right now (no period): orders awaiting payment and their total, paid orders to ship, published / low-stock / sold-out product counts, the 8 latest orders (number, time, status, total, customer name, country, animals), the 8 emptiest published products at or below their threshold |
| GET | `/admin/stats/sales?from=&to=` | `kpis` (revenue, paidRevenue, orders, averageOrderValue, animalsSold, newAccounts — customer accounts registered —, returningCustomerShare — share of sales from emails that had ordered before —, cancelledOrders, cancellationRate — of all orders placed), each with `previous` and `changeBps`; `series` without gaps (per bucket: revenue, orders and animals, total and split into paid / awaiting payment); `byStatus` (all orders placed, by current status); `byWeekday` (sales, Monday = 1, all seven days); `byCountry` (sales by delivery country) |
| GET | `/admin/stats/products?from=&to=&limit=10` | `topProducts` (best sellers by revenue: current name and grade, units, packs; `limit` 1–50), `byCategory` (current category of the product), `bySpecies` (species stored with the sale; `name: null` for lines without a species) |
| GET | `/admin/stats/stock?from=&to=` | From the stock ledger: `restocked`, `sold` (order movements net of cancellations), `lost`, `lossRate` (lost ÷ (sold + lost)), each compared with the period before; `byReason` (net change per reason, largest first) |
| GET | `/admin/stats/sales/export?from=&to=` | CSV download (`text/csv`, UTF-8, CRLF), one row per day of the period including empty days: `date, orders, paid_orders, revenue_gross_eur, vat_eur, shipping_eur, revenue_net_eur, animals`. Contains no personal data |

### 3.2 Products

Built in Phase 6. Every change answers with the full product (`AdminProductView`), so
the editor always shows what was saved.

| Method | Path | Description |
|---|---|---|
| GET | `/admin/products?q=&status=&categoryId=&stock=&sort=&page=&size=` | All products incl. drafts and archived, with exact stock. `q` matches name, web address and SKUs; `stock` = `ALL` (default), `LOW_STOCK` (1 … threshold), `OUT_OF_STOCK` (0); `sort` = `UPDATED_DESC` (default), `NAME_ASC`, `STOCK_ASC`. Also the stock overview |
| POST | `/admin/products` | Create → `201`, status `DRAFT`, stock 0 |
| GET | `/admin/products/{id}` | Full detail: fields, `version`, stock, availability, pack sizes, photos, `publishProblems` |
| PUT | `/admin/products/{id}` | Save details; send the `version` you loaded. Stale → `409 CONFLICT`, missing → `422 VERSION_REQUIRED` |
| POST | `/admin/products/{id}/publish` | → `ACTIVE`. Refused with `422 SPECIES_RESTRICTED`, `NO_ACTIVE_VARIANT` or `NO_IMAGE` |
| POST | `/admin/products/{id}/archive` | → `ARCHIVED` (out of the shop, kept for orders and history) |
| POST | `/admin/products/{id}/duplicate` | → `201` unpublished copy without stock and photos; web address and SKUs get a free `-copy` suffix |
| POST | `/admin/products/{id}/variants` | Add a pack size → `201` |
| PUT | `/admin/products/{id}/variants/{variantId}` | Change a pack size; `active: false` stops selling it (pack sizes are never deleted, orders refer to them) |
| POST | `/admin/products/{id}/images` | Multipart `file` + `altText` → `201` |
| PATCH | `/admin/products/{id}/images/order` | `{ imageIds: [...] }` – every photo once; the first is the main photo |
| PATCH | `/admin/products/{id}/images/{imageId}` | `{ altText }` |
| DELETE | `/admin/products/{id}/images/{imageId}` | Delete; files are removed after the change is saved. The last photo of a published product → `422 LAST_IMAGE` |
| POST | `/admin/markdown/preview` | `{ markdown }` → `{ html }` rendered with the shop's sanitiser |

**Product fields** (`POST`/`PUT`): `name` (≤150), `slug` (optional; derived from the
name, lower-case letters, digits and hyphens, unique → `409 SLUG_TAKEN`,
`422 SLUG_INVALID`), `categoryId`, `speciesId?`, `gradeId?`, `colourIds[]`,
`shortDescription?` (≤300), `description?` and `careNotes?` (Markdown), `liveAnimal`,
`featured`, `lowStockThreshold`, `availableFrom?`, `taxRateBps` (1900 = 19 %), `seoTitle?`,
`seoDescription?`, `version` (update only). Stock is never part of this request; it
changes only through §3.4, so a sale while the editor is open does not cause a conflict.

**Pack size fields:** `sku` (letters, digits, `. _ -`, stored upper-case, unique →
`409 SKU_TAKEN`), `name`, `packSize` (animals, 1–1000), `priceCents` (gross),
`compareAtPriceCents?` (must be higher → `422 COMPARE_AT_PRICE_INVALID`), `active`. The
owner sets prices here; customer requests never carry prices.

**Photos:** JPEG, PNG or WebP (detected from the file content, not its name), at most
15 MB (`413 FILE_TOO_LARGE`), 40 megapixels and 12 000 px per side
(`422 IMAGE_TOO_LARGE`, checked before decoding), at least 400 px wide
(`422 IMAGE_TOO_SMALL`). Unreadable → `422 IMAGE_INVALID`, other types →
`422 IMAGE_TYPE_UNSUPPORTED`. The photo is turned upright (EXIF orientation) and
re-encoded from its pixels into WebP renditions 400/800/1200/1600 px wide (up to its own
width), which drops all metadata (camera, GPS) and anything hidden in the file. Up to 20
photos per product (`422 IMAGE_LIMIT_REACHED`).

### 3.3 Taxonomy

`GET` list, `POST` (→ `201`), `PUT /{id}`, `DELETE /{id}` (→ `204`) for
`/admin/categories`, `/admin/species` (plus `GET /admin/species/{id}`), `/admin/colours`,
`/admin/grades`. Lists include `productCount`. Slugs follow the product rules.

- **Categories:** `name`, `slug?`, `parentId?`, `description?`, `sortOrder`, `active`
  (inactive ones are hidden from the shop navigation). Placing a category inside its own
  branch → `422 CATEGORY_CYCLE`.
- **Species:** `scientificName` (unique → `409 SCIENTIFIC_NAME_TAKEN`), `commonName?`,
  `slug?`, `description?` (Markdown), `origin?`, care data (`tempMinC`/`tempMaxC`,
  `phMin`/`phMax`, `ghMin`/`ghMax`, `khMin`/`khMax`, `tdsMin`/`tdsMax`, `adultSizeMm`,
  `lifespanMonths`, `difficulty`), `tradeRestricted`, `restrictionNote?`. A minimum above
  its maximum → `422 RANGE_INVALID`. Marking a species as restricted removes all its
  products from the shop at once.
- **Colours:** `name`, `slug?`, `hexCode?` (`#RRGGBB`), `sortOrder`.
- **Grades:** `name`, `slug?`, `scale?`, `description?`, `rank` (0–1000, higher is better),
  `sortOrder`.

Deleting something still used by a product (or a category with sub-categories) →
`409 IN_USE`.

### 3.4 Inventory

The stock overview is the product list with its `stock` filter (§3.2).

| Method | Path | Description |
|---|---|---|
| POST | `/admin/inventory/{productId}/adjustments` | `{ delta, reason, note? }` → `{ productId, stockUnits }`. `RESTOCK` and `RETURN` add (positive), `LOSS` removes (negative), `MANUAL_ADJUSTMENT` either way; anything else → `422 ADJUSTMENT_INVALID`. Removing more than is in stock → `422 STOCK_NEGATIVE` |
| PUT | `/admin/inventory/{productId}/count` | `{ countedUnits, note? }` – stocktake: the counted number becomes the stock, the difference is recorded as `MANUAL_ADJUSTMENT` with the note "Stocktake: …" |
| GET | `/admin/inventory/{productId}/movements?page=&size=` | Stock history, newest first: `delta`, `stockAfter`, `reason`, `note`, `orderId`, `manual`, `createdAt` |

Every change is a conditional SQL update (the stock can never become negative, also with
simultaneous changes), a ledger entry and an audit record in one transaction.

## 6. Order status and payment status reference

| `status` | Meaning | Customer sees |
|---|---|---|
| `PENDING_PAYMENT` | Order placed, waiting for payment; stock reserved | "Awaiting payment" |
| `PAID` | Payment confirmed | "Payment received" |
| `PROCESSING` | Being packed / waiting for the next dispatch day | "Being prepared" |
| `SHIPPED` | Handed to carrier, tracking available | "Shipped" + tracking |
| `DELIVERED` | Delivered | "Delivered" |
| `CANCELLED` | Cancelled; stock returned if not shipped | "Cancelled" |

`paymentStatus`: `UNPAID`, `PAID`, `PARTIALLY_REFUNDED`, `REFUNDED`, `FAILED`.
